# 第四章：位置编码（Positional Encoding）

第三章结尾发现了一个问题：同一个词“东”出现在 $t=1$ 和 $t=4$ 两个位置，词向量完全相同，都不包含显式的位置坐标。本章将在不改变词向量维度的前提下，为每个位置加入不同的位置信号。

---

## 4.1 为什么模型需要位置信息？

想象一个极端情况。对于下面两个序列：

$$[\text{哈尔滨},\ \text{东},\ \text{站}] \quad \text{和} \quad [\text{站},\ \text{东},\ \text{哈尔滨}]$$

它们包含完全相同的 token，只是顺序不同。在矩阵 $X$ 中，两者是同一组行向量的不同排列。Causal Mask 虽然能规定“只能看左边”，却不会把当前位置直接写进输入向量。

语言的意义高度依赖词序。“哈尔滨东站在东边”和“东边在哈尔滨东站”意思截然不同。

**解决方案**：给每个位置叠加一个独特的“坐标戳”，直接加到词向量上。这就是位置编码（Positional Encoding）。

---

## 4.2 为什么不直接使用位置序号？

### 4.2.1 数值干扰与长度泛化

最直觉的做法，是把位置编号 $t=0,1,2,\ldots$ 直接加到词向量中。但这样有两个问题：

- **数值越来越大**：词向量大多在 $[-1,1]$ 内，位置编号却会变成 10、100，容易压过原来的词向量。
- **不利于处理更长序列**：推理时遇到训练中没有见过的位置编号，模型不一定知道怎样使用。

用三角函数（$\sin$ 和 $\cos$）编码位置，可以让数值始终保持在 $[-1,1]$ 内，而且不同位置之间具有规律性的变化。

### 4.2.2 三角函数编码的优势

三角函数编码的优势是无需训练额外的位置参数、值域稳定，而且不同位置之间存在规律性的几何关系，有助于模型处理训练中未见过的位置。


### 4.2.3 其他位置编码方案与历史脉络

位置编码的思想并非 2017 年凭空出现，它的根源可以追溯到更早的序列建模研究。

**2014–2015年：RNN 的天然位置感知**

在 Transformer 诞生之前，序列建模的主流架构是循环神经网络（RNN）及其变体 LSTM 和 GRU。RNN 的核心特征是**逐个位置串行处理**——输入位置 0，计算隐藏状态，再输入位置 1，更新隐藏状态……这种天然的时序结构，让 RNN 隐式地拥有了位置感知能力：它不需要额外的位置编码，因为处理顺序本身就是位置信息。

但 RNN 有一个致命缺陷：**无法并行化**。每个位置的隐藏状态依赖前一个位置的输出，序列中的第 100 个词必须等前面 99 个词全部处理完才能开始计算。当序列变长时，这种串行依赖成为训练速度的瓶颈。

**2016—2017 年：卷积替代 RNN 的尝试**

为了解决 RNN 的并行化问题，研究者尝试把卷积神经网络（CNN）用于序列建模。2017 年，Gehring 等人发表 ConvS2S，用堆叠卷积层替代循环结构。模型可以并行处理同一层的多个位置，但也需要明确告诉网络每个 token 在哪里。

ConvS2S 的解决方案是**显式地给每个位置加一个“位置嵌入”**——一个与词向量维度相同的可学习向量，代表该位置的绝对坐标。在训练过程中，这些位置嵌入和词嵌入一起被优化。这是“位置编码”这一思想的早期实践之一。

**2017年：Transformer 的革命与正弦编码的诞生**

2017 年，Vaswani 等人在设计 Transformer 时，面临着类似的问题：**Attention 可以并行处理所有位置，但只根据 token 内容计算时，不会自动得到每个 token 的位置坐标。**

Transformer 需要一个位置编码方案。Vaswani 等人比较了两种选择：

- **可学习的位置嵌入**：让模型在训练中学习每个位置的表示，简单直观。
- **三角函数编码**：用固定的正弦和余弦函数生成位置，不增加可训练参数，而且位置之间的变化有规律。

原始 Transformer 采用了**三角函数编码**。论文指出，对于固定的距离 $k$，位置 $t+k$ 的编码可以由位置 $t$ 的编码通过固定的线性变化得到，因此模型有机会学习相对位置关系。

> **翻译成直觉**：位置向前移动固定的 $k$ 步，正弦和余弦也会按照固定规律变化。模型因此有机会学习“相距 $k$ 个位置”意味着什么，而不必死记每个位置。

后来又出现了可学习位置嵌入、相对位置编码、RoPE 和 ALiBi 等方案。本章先手算原始 Transformer 使用的经典三角函数编码，第 22 章再讨论现代 LLM 中常见的 RoPE。

## 4.3 位置编码公式

标准 Transformer 的位置编码公式为：

$$P[t,\ 2i] = \sin\!\left(\frac{t}{10000^{2i/d_{model}}}\right)$$

$$P[t,\ 2i+1] = \cos\!\left(\frac{t}{10000^{2i/d_{model}}}\right)$$

其中 $t$ 是位置（从 0 开始），$i$ 是维度对的索引（从 0 开始），$d_{model}$ 是向量维度。

公式中的三角函数都使用**弧度**。当序列长度为 $N$ 时，位置编码矩阵的 shape 为：

$$
P\in\mathbb{R}^{N\times d_{model}}
$$

本书取 $N=10$、$d_{model}=3$，因此 $P\in\mathbb{R}^{10\times3}$，可以与第三章得到的 $X\in\mathbb{R}^{10\times3}$ 逐元素相加。

**本书的特殊处理**：$d_{model}=3$ 时，标准公式会产生三列，但第三列（$i=1$ 时，$2i=2$，对应索引2）对应的频率是：

$$P[t,\ 2] = \sin\!\left(\frac{t}{10000^{2/3}}\right) = \sin\!\left(\frac{t}{464.16}\right)$$

在 $t=0$ 到 $t=9$ 的范围内，$t/464.16$ 最大只有 $9/464.16\approx0.0194$，第三列变化很小，不方便观察。

因此，本书对第三列改用手工设计的低频正弦：

$$P[t,\ 0] = \sin(t), \quad P[t,\ 1] = \cos(t), \quad P[t,\ 2] = \sin\!\left(\frac{t}{100}\right)$$

第三列使用 $\sin(t/100)$：在 $t=0$ 到 $t=9$ 范围内，值从 0 平滑增长到 $\sin(0.09)\approx0.0899$。它变化较慢，又比原公式更容易观察。

> **这是本书为了手算做的调整**：第三列的分母从约 464.16 改为 100。前两列仍是标准公式得到的 $\sin(t)$ 和 $\cos(t)$。后面的全部计算都以本书这三个公式为准。

正弦和余弦满足角度加法公式，因此固定的位置间隔会带来固定的变化规律。这也是三角函数位置编码能够表达相对距离的原因。

## 4.5 叠加到词向量：得到 $X_{final}$

> 本节统一使用未截断的三角函数值完成加法，最后将结果四舍五入到小数点后 8 位。手算复核时，可以直接使用上表已经保留 8 位小数的 $P$；由此引入的误差最多出现在更低位。4.7 节代码会另外打印 4 位小数版本，便于快速核对。

将词向量矩阵 $X$（第三章得到）与位置编码矩阵 $P$ 直接相加：

$$X_{final} = X + P$$

两边 shape 完全一致，因此这里是逐元素相加：

$$
(10\times3)+(10\times3)=(10\times3)
$$

## 4.6 验证：两个“东”现在不同了吗？

回到第三章提出的问题。原来两个“东”的词向量相同，加上位置编码之后：

| | 词向量 $X[t,:]$ | 位置编码 $P[t,:]$ | $X_{final}[t,:]=X[t,:]+P[t,:]$ |
|:--:|:--:|:--:|:--:|
| $t=1$（站名“东”）| $[0.9,\ 0.1,\ 0.0]$ | $[0.84147098,\ 0.54030231,\ 0.00999983]$ | $[\mathbf{1.74147098},\ \mathbf{0.64030231},\ \mathbf{0.00999983}]$ |
| $t=4$（方位“东”）| $[0.9,\ 0.1,\ 0.0]$ | $[-0.75680250,\ -0.65364362,\ 0.03998933]$ | $[\mathbf{0.14319750},\ \mathbf{-0.55364362},\ \mathbf{0.03998933}]$ |

两个输入行现在不再相同。位置编码直接打破了输入层的位置对称性，因此在进入 Attention 之前，两个“东”已经能够产生不同的 Query、Key 和 Value。后续 Attention 还会结合各自可见的前缀内容，进一步形成不同的上下文表示。

def format_array(array, precision):
    """用固定小数位打印，便于与书中的手算结果逐项核对。"""

        array,
        formatter={"float_kind": lambda value: f"{value: .{precision}f}"},

## 4.8 本章小结

本章完成了位置编码的全部计算：

**① 明确问题**：词向量本身不含位置信息，同一 token 在不同位置会查到相同的向量。

**② 公式设计**：前两列使用标准三角函数 $\sin(t)$、$\cos(t)$；第三列因为原公式在 $N=10$ 范围内变化太小，改用便于观察的 $\sin(t/100)$。

**③ 计算 $P$**：得到 $10\times3$ 的位置编码矩阵。在 $t=0$ 到 $t=9$ 的当前范围内，每行都不同，所有值都在 $[-1,1]$ 之间。

**④ 叠加得 $X_{final}$**：$X_{final}=X+P$，维度不变，仍为 $10\times3$，但每个输入行已经携带当前位置的信号。原本相同的两个“东”，加位置编码后变为 $[1.74147098,\ 0.64030231,\ 0.00999983]$ 和 $[0.14319750,\ -0.55364362,\ 0.03998933]$，不再相同。

$X_{final}$ 是最终送入 Transformer 后续计算的输入矩阵。从第五章开始，所有 Attention 计算都以 $X_{final}$ 为起点。
