# 第零章：大模型是什么

在正式开始手算之前，我们需要先建立一个正确的心智模型。

很多人对"大模型"的第一印象是：一个神秘的AI，像人类一样思考，有某种难以言说的智能。

这个印象是错的。

本章先把大模型最核心的组成和工作方式讲清楚。你会发现，它并非不可拆解的黑箱；至少在本书讨论的范围内，每个关键部件都可以用明确的数学运算来描述。

---

## 0.1 大模型的本质：一堆浮点数

GPT、Claude、Gemini、通义千问、DeepSeek、Kimi……

这些能够对话、写代码、回答问题、生成内容的大模型，本质上是什么？

很多人的第一反应是：

> 一个会思考的 AI。

或者：

> 一个拥有知识和智慧的数字大脑。

但从工程角度看，它们的本质其实非常具体。

从存储角度看，训练完成的大语言模型通常以一个或多个巨大的参数文件保存；从数学角度看，它是由网络结构和这些参数共同定义的高维函数。参数文件记录模型学到的权重，网络配置和推理程序则规定这些权重如何参与计算。

这些参数通常以 float32、float16 或 bfloat16 等浮点格式表示，也可能在部署时被量化为更低位宽。公开模型的参数量可以从数亿到数千亿；一些闭源模型没有公布具体规模。

这些浮点数是什么？

它们是各种矩阵中的参数，例如：

```text
W_E（词嵌入矩阵）
W_Q（Query 投影矩阵）
W_K（Key 投影矩阵）
W_V（Value 投影矩阵）
W_1 / W_2（前馈网络权重）
W_O（输出投影矩阵）
……
```

训练所形成的统计规律和能力，主要编码在这些参数的整体结构之中。模型运行时还会受到输入上下文、解码策略和外部工具等因素影响，因此不能把完整的模型系统简单等同于一个参数文件。

当你打开这些模型时，输入一句话时，后台发生的事情大致如下：

1. 把文字转换成 token 索引序列
2. 将数字序列输入模型
3. 与模型参数进行大量数值计算
4. 得到下一个 token 的概率分布
5. 从概率分布中选择一个 token
6. 重复上述过程，直到生成完整回答

从计算过程来看，模型所执行的操作全部可以分解为：

* 矩阵乘法
* 非线性变换
* 概率计算

没有神秘机制，只有大量数值计算。

当然，不同模型之间仍然存在许多差异：

* 参数规模不同
* 训练数据不同
* 模型结构细节不同
* 工程优化方案不同

但无论是 GPT、Claude、Gemini，还是通义千问、DeepSeek、Kimi，它们大多以 Transformer 架构为核心，并在注意力机制、归一化方式、训练策略和工程优化方面不断演进：

> 用大量参数构成一个函数，根据前面的内容预测下一个 token 的概率分布。

这就是为什么本书要手算一个只有 156 个参数的模型——

**把这 156 个数字彻底算明白，你就理解了现代 Transformer 语言模型最核心的计算机制。**

## 史海钩沉：这个想法的源头——从 McCulloch-Pitts 到 Transformer

“大模型的本质是一堆浮点数”——这句话在今天听起来平淡无奇，但它背后有一段跨越八十余年的思想史。

**1943年：神经元的数学抽象**

1943年，神经生理学家 Warren McCulloch 和数学家 Walter Pitts 在论文《A Logical Calculus of Ideas Immanent in Nervous Activity》中，提出了一个革命性的想法：**人脑的神经元可以用数学逻辑来抽象。** 他们把一个神经元简化为：接收多个输入信号，如果总和超过阈值，输出 1；否则输出 0。这个极度简化的模型后来被称为 **McCulloch-Pitts 神经元**。

今天看来，这个模型过于简单——它没有可训练权重，无法从数据中学习，而且只能处理二值信号。但它是早期以数学形式描述神经计算的代表性工作之一。**从那一刻起，智能不再只是一个哲学命题，它也开始成为可以形式化研究的问题。**

**1958年：感知器——第一个可训练的神经网络**

1958年，Frank Rosenblatt 在 Cornell 大学制造了 **感知器（Perceptron）**——一个真正能"学习"的机器。感知器在 McCulloch-Pitts 神经元的基础上加了一个关键创新：**每个输入都有一个可调节的权重。** 通过反复展示样本和调整权重，感知器可以学会区分简单的模式（比如识别字母）。

Rosenblatt 的感知器只有一层，只能处理线性可分的任务。但它证明了一件事：**机器的参数可以通过训练自动调整，而不需要人工预设。** 这正是今天大模型训练的雏形——从 156 个参数到 1750 亿个参数，原理都是"自动调整那堆数字"。

**1986年：反向传播的成熟**

反向传播并非突然出现。Linnainmaa 在 1970 年系统描述了反向模式自动微分，Werbos 在 1974 年讨论了将其用于神经网络训练。1986 年，Rumelhart、Hinton 和 Williams 发表论文，系统展示并推广了用反向传播训练多层神经网络的方法，使这一方法得到广泛关注。

**1997年：LSTM 缓解长距离依赖问题**

普通 RNN 在处理长距离依赖时容易受到梯度消失和梯度爆炸的影响。1997 年，Hochreiter 和 Schmidhuber 提出 LSTM，通过门控机制改善长期信息的保留。2014 年提出的 GRU 延续了门控循环网络这条路线。它们并没有消除循环计算的全部限制，但为序列建模积累了重要经验。

**2014年：Bahdanau Attention 的出现**

2014 年，Dzmitry Bahdanau 等人在神经机器翻译中引入可学习的对齐机制，让模型在生成每个输出时动态关注输入的不同位置。三年后，Vaswani 等人进一步提出完全基于 Attention 的 Transformer，摆脱了 RNN 的顺序递归计算。

**2017年至今：Transformer 时代的爆发**

从 2017 年的 Transformer，到 2018 年的 BERT 和 GPT，再到此后的 GPT、Claude、Gemini、Llama、Qwen 和 DeepSeek 等模型，Transformer 逐渐成为大语言模型的主流架构。模型在注意力机制、归一化方式、训练目标、数据工程和推理系统等方面持续演进；对于没有公开结构和参数规模的闭源模型，本书不作未经证实的推断。

**从 1943 年 McCulloch-Pitts 的二值神经元，到 1958 年 Rosenblatt 的可训练感知器，到 1986 年反向传播的广泛传播，再到 2017 年的 Transformer 和今天这个 156 参数的极简模型——“把智能编码为数字”这条研究路线，经过八十余年的发展，从理论设想逐步变成了工程现实。** 你接下来要手算的每一个数字，都是这条思想长河中的一个坐标点。

## 0.2 模型其实是一个函数

从数学角度看，大模型本质上是一个函数：

> 输入 token 序列 $\rightarrow f_\theta(x) \rightarrow$ 输出概率分布

其中：

* $x$ 表示输入序列
* $\theta$（Theta）表示模型全部参数
* $f$ 表示 Transformer 所定义的计算过程

训练时：

```text
固定输入 x
不断调整 θ
```

推理时：

```text
固定 θ
输入新的 x
```

因此：

> 大模型并不是一个神秘实体，而是一个由大量参数定义出来的巨大数学函数。

## 0.3 训练是什么：让这堆数字越来越准

大模型"学习"的过程，本质上是：

**反复调整那堆浮点数，让模型的预测越来越接近正确答案。**

整个训练流程是一个循环，每次循环做四件事：

```
┌─────────────────────────────────────────────────────────┐
│                     训练循环                             │
│                                                         │
│  ① 前向传播                                              │
│     输入文字 → 矩阵乘法 → 输出预测概率 P                   │
│                                                         │
│  ② 计算损失                                              │
│     对比预测 P 和正确答案 Y → 得到损失值 L                 │
│     （L 越大表示预测越差）                                │
│                                                         │
│  ③ 反向传播                                              │
│     从损失 L 出发，用链式法则计算每个参数对损失的贡献       │
│     得到梯度 ∂L/∂W（每个参数应该往哪个方向调整）           │
│                                                        │
│  ④ 参数更新                                             │
│     W ← W - η × ∂L/∂W                                  │
│     沿梯度反方向微调每个参数                             │
│                                                        │
│  重复 ↑，直到满足停止条件或达到 500 个 epoch              │
└─────────────────────────────────────────────────────────┘
```

这个循环需要重复许多次。GPT-3 的训练语料规模约为 3000 亿个 token；本书的极简模型则按预先设定的收敛条件训练，最多运行 500 个 epoch。

本书采用 full-batch 训练：5 句话分别完成前向传播，得到各自的损失；将 5 个损失取平均后，再基于平均损失执行一次反向传播和参数更新。由于这个 batch 已经覆盖全部训练数据，一次参数更新也就完成了对整个训练集的一次遍历，即 1 个 epoch。

<!-- 训练与推理结果的复算脚本、日志和 checkpoint 见本目录的计算核验说明。 -->

> **训练结果：**按本书的 full-batch 梯度下降口径运行至第 500 个 epoch，仍未满足收敛条件（连续 10 个 epoch 的 $\Delta L_e=|L_e-L_{e-1}|$ 均小于 $0.001$）；因此收敛 epoch 记为“未满足（500）”，不能写成已经收敛。日志和参数见[计算核验说明](./计算核验/README.md)。

> 本章约定 $L_e$ 为第 $e$ 个 epoch 参数更新完成后，使用更新后的同一组参数重新计算得到的 full-batch 平均损失：每句话先对未被 Loss Mask 屏蔽的有效预测位置取平均，得到 $L_{\text{seq}}^{(i)}$，再计算 $L_e=\frac{1}{5}\sum_{i=1}^{5}L_{\text{seq}}^{(i)}$。这样，收敛判定、最终损失和推理检查点都对应同一个 checkpoint。

小模型和大模型训练循环的核心逻辑相通，但数据规模、优化器和工程系统会复杂得多。

## 0.4 推理是什么：用这堆数字生成文字

训练完成后，参数固定下来，保存成文件。

从参数计算角度看，推理阶段只执行**前向传播**，不会反向传播或更新参数。完整的文本生成系统还需要重复执行采样、拼接和停止条件判断。

```
┌──────────────────────────────────────────────────────────┐
│                     推理循环                              │
│                                                          │
│  ① 读取参数文件（加载所有矩阵到内存/显存）                  │
│                                                          │
│  ② 前向传播                                               │
│     输入当前序列 → 矩阵乘法 → 输出下一个 token 的概率分布 P  │
│                                                          │
│  ③ 采样                                                  │
│     从 P 中选一个 token（贪心 / temperature / top-p）       │
│                                                          │
│  ④ 拼接                                                  │
│     把选出的 token 加到序列末尾                            │
│                                                          │
│  重复 ↑，直到生成 <EOS>（结束符）                          │
└──────────────────────────────────────────────────────────┘
```

**训练与推理最关键的区别是：训练会更新参数，推理不会。** 其他常见差异如下：

| | 训练 | 推理 |
|:--|:--|:--|
| 参数状态 | 每步更新 | 固定不变 |
| 是否有反向传播 | ✓ 有 | ✗ 没有 |
| 是否有损失函数 | ✓ 有 | ✗ 没有 |
| 是否有 KV Cache | 通常不使用 | 自回归生成时通常使用（见第19章） |
| 目的 | 调整参数 | 生成文字 |
| 单次计算 | 前向传播 + 反向传播 | 仅前向传播；完整生成需要重复多次 |

推理就是：**加载训练好的参数，执行前向传播，选择下一个 token，然后重复。**

实际工程实现中通常使用 KV Cache，以避免重复计算历史 token。

## 0.5 梯度下降：沿最陡的方向下山

训练循环里最关键的步骤是"反向传播 + 参数更新"。

为什么参数要按梯度方向更新？这背后有一个简单而深刻的数学直觉。

### 一个直觉比喻

把损失函数想象成一座山的地形图。你站在山上某个位置（当前参数值），目标是走到山谷（损失最小的地方）。

- **梯度**：当前位置最陡的上升方向
- **负梯度**：当前位置最陡的下降方向
- **学习率 $\eta$**：每步走多远

参数更新公式 $W \leftarrow W - \eta \cdot \frac{\partial L}{\partial W}$ 就是：

> 沿最陡下降方向，走一小步。

### 手算一个最简单的例子

设损失函数 $L(w) = (w - 3)^2$，最小值在 $w = 3$，初始值 $w = 0$，学习率 $\eta = 0.3$。

梯度（导数）：$\frac{\partial L}{\partial w} = 2(w - 3)$

| Step | $w$ | $L(w)$ | 梯度 $\frac{\partial L}{\partial w}$ | 更新量 $-\eta \times$梯度 |
|:--:|:--:|:--:|:--:|:--:|
| 0 | 0.0000 | 9.0000 | −6.0000 | +1.8000 |
| 1 | 1.8000 | 1.4400 | −2.4000 | +0.7200 |
| 2 | 2.5200 | 0.2304 | −0.9600 | +0.2880 |
| 3 | 2.8080 | 0.0369 | −0.3840 | +0.1152 |
| 4 | 2.9232 | 0.0059 | −0.1536 | +0.0461 |
| 5 | 2.9693 | 0.0009 | −0.0614 | +0.0184 |
| 6 | 2.9877 | 0.0002 | −0.0246 | +0.0074 |
| 7 | 2.9951 | 0.0000 | −0.0098 | +0.0029 |
| 8 | 2.9980 | 0.0000 | −0.0039 | — |

**经过 8 次参数更新，$w$ 从 0.0 走到了 2.9980，非常接近目标值 3.0。** 表中的第 8 行展示更新后的终态，因此不再继续计算更新量。

每一步：梯度为负（$w$ 小于目标值 3），更新量为正，$w$ 向右移动，损失下降。随着 $w$ 接近 3，梯度趋近于 0，步长自动缩小，自然收敛。

你也可以把 $L(w) = (w-3)^2$ 画成一条抛物线，$w=3$ 就是谷底；梯度告诉你当前在坡的哪一侧，负梯度就是朝谷底走。

### 学习率的重要性

| 学习率 η | 现象 |
|:--|:--|
| 0.1 | 稳定收敛，但较慢 |
| 0.3 | 快速收敛 ✓ |
| 0.9 | 振荡收敛 |
| 1.0 | 持续震荡，不收敛 |
| 1.1 | 发散 |

> 这些分界只适用于当前的二次函数 $L(w)=(w-3)^2$ 和基础梯度下降，不是所有模型通用的学习率阈值。真实神经网络能否稳定训练取决于损失曲率、优化器、batch、数值精度等多种因素。

当学习率逐渐增大时，参数更新会越来越激进。

* η 较小时，下降稳定但速度慢；
* η 接近 1 时，参数会在最优点两侧来回震荡；
* η 大于 1 时，更新过度，误差会不断放大，最终发散。

这也是深度学习训练中学习率选择如此重要的原因。在真实 Transformer 中，损失函数不是二维曲面，而是分布在高维参数空间里的复杂地形；本书把它缩小到 1 个参数，方便先看清更新方向。

### 从 1 个参数到 156 个参数

上面的例子只有 1 个参数 $w$。本书的模型有 156 个参数（$W_Q$、$W_K$、$W_V$ 等每个矩阵里的数值）。

**基本更新规则相同**——每个可训练参数都有对应的梯度，并按照优化规则进行更新。在本书采用的基础梯度下降中：

$$W_Q \leftarrow W_Q - \eta \cdot \frac{\partial L}{\partial W_Q}$$
$$W_K \leftarrow W_K - \eta \cdot \frac{\partial L}{\partial W_K}$$
$$\vdots$$

从损失出发，用链式法则逐层求出 156 个参数对应的梯度，这就是本书将要展开的反向传播过程。

GPT-3 有 1750 亿个参数，训练时同样需要计算梯度并由优化器更新参数。真实大模型还会使用 AdamW、学习率调度、梯度裁剪、混合精度和分布式训练等技术，但梯度所表达的核心信息仍然是：参数朝哪个方向变化，会让损失下降。

## 0.6 本书的极简模型：156 个可训练参数

现在你已经知道大模型的本质是什么。让我们看看本书的模型长什么样。

**训练数据（5 句话）：**

```text
哈尔滨东站在东边。
哈尔滨西站在西边。
哈尔滨南站在南边。
哈尔滨北站在北边。
哈尔滨站在里边。
```

**词表（12 个 token）：**

```
哈尔滨、站、在、东、南、西、北、里、边、。、<Pad>、<EOS>
```

**模型维度：3**

> 每个 token 用 3 维向量表示：$d_{model} = 3$

三维向量有一个独特的教学优势：方位词（东、南、西、北）可以在三维空间中呈现出直观的几何结构。我们可以把 token embedding 画出来，直接观察训练前后表示空间发生了什么变化。

**上下文长度：10**

> 模型一次最多处理 10 个 token：$N = 10$

**FFN 隐藏层维度：6**

> $d_{ffn} = 6 = 2 \times d_{model}$。这是为了控制手算规模而采用的教学设定，并非标准 Transformer 的固定比例；原始 Transformer 的 FFN 隐藏维度通常约为 $4 \times d_{model}$，现代架构还会采用其他比例和门控 FFN。


**全部可训练参数如下：**
```
model.safetensors
├── W_E     12×3  =  36 个数值   词向量查找表（手工几何设计）
├── W_Q      3×3  =   9 个数值   Query 投影（Xavier 初始化）
├── W_K      3×3  =   9 个数值   Key 投影（Xavier 初始化）
├── W_V      3×3  =   9 个数值   Value 投影（Xavier 初始化）
├── W_1      3×6  =  18 个数值   FFN 第一层（Kaiming 初始化）
├── b_1        6  =   6 个数值   FFN 第一层偏置（零初始化）
├── W_2      6×3  =  18 个数值   FFN 第二层（Xavier 初始化）
├── b_2        3  =   3 个数值   FFN 第二层偏置（零初始化）
├── W_O     3×12  =  36 个数值   输出投影（Xavier 初始化）
├── γ₁, β₁     3  =   6 个数值   LayerNorm 1（全1 / 零初始化）
└── γ₂, β₂     3  =   6 个数值   LayerNorm 2（全1 / 零初始化）
                   ────────────
                    合计 156 个 float32
                    原始张量数据 624 字节（156 × 4 = 624 字节）
```
> 624 字节只表示 156 个 float32 数值本身占用的空间。实际 `.safetensors` 文件还包含张量名称、形状、数据类型和偏移量等头部信息，因此文件总大小会大于 624 字节。本书手算另按第 2 章约定，以 8 位小数初值和 float64 继续运算；这里的 float32 仅用于存储量示意。

> $W_E$ 采用手工几何设计，而非随机初始化——这是为了让读者在训练前就能直观看到 token embedding 的空间关系。真实大语言模型从头训练时，embedding matrix 通常经过随机或受控初始化，再通过训练学习；本书的特殊初始化只服务于教学可视化，$W_E$ 后续仍然参与训练。

> 位置编码 $P$ 是固定设计的常量，Causal Mask 和 Pad Mask 也不包含可训练数值，因此它们不计入 156 个可训练参数。

> **符号约定：** 本书的 $W_O\in\mathbb{R}^{3\times12}$ 指从模型内部表示映射到词表 logits 的输出投影。多头注意力文献也常把注意力模块内部的输出投影记为 $W_O$；本书前 19 章使用单头注意力，没有单独设置那个 $3\times3$ 投影，二者不要混淆。


> **关于 FFN 内部两层与 Transformer 层的关系**
>
> 在我们的模型里：
>
> - FFN 第一层：$3 \times 6$ 矩阵 + 6 个偏置（升维：$3 \rightarrow 6$）
> - FFN 第二层：$6 \times 3$ 矩阵 + 3 个偏置（降维：$6 \rightarrow 3$）
>
> 这里的"第一层/第二层"指 FFN 模块**内部**的两次线性变换，不是 Transformer 的两层。整个 Transformer 仍然只有 1 层，包含：
>
> Self-Attention 模块 + 残差 + LayerNorm → FFN 模块 + 残差 + LayerNorm
>
> 换句话说：**Transformer 1 层 = 1 个 Attention + 1 个 FFN**，FFN 内部的两次线性变换只是完成升维→激活→降维的操作。

**训练完成后，如何验证模型？**

在第 500 个 epoch 停止后，用同一个最终 checkpoint 对下面两个检查点运行确定性前向传播，并从对应位置的 softmax 分布中读取结果：

| 检查点 | 输入 token 序列 | 训练语料给出的预期目标 | 实际 Top-1 token | 目标 token 概率 |
|:--|:--|:--|:--|:--|
| 站名补全 | `[哈尔滨, 东]`（索引 `[0, 3]`） | `站` | `站` | `0.546663` |
| 句子结束 | `[哈尔滨, 东, 站, 在, 东, 边, 。]`（索引 `[0, 3, 1, 2, 3, 8, 9]`） | `<EOS>` | `<EOS>` | `0.796258` |

> **推理复算口径：** 使用第 500 个 epoch 的最终 checkpoint，关闭采样并执行确定性前向传播；输入按 $N=10$ 补齐并应用与训练相同的 Causal Mask 和 Pad Mask。站名补全读取 $t=1$ 行的 logits，句子结束检查读取 $t=6$ 行的 logits。对相应行执行 softmax 后，以 `argmax` 得到实际 Top-1 token，并读取目标 token 所在列的概率。

> **训练摘要：**第 500 个 epoch 更新后，重新执行五句前向传播，full-batch 平均损失为 `0.844642290`。此数值和上表推理结果来自同一个最终 checkpoint；停止原因是达到 500 个 epoch 的上限，而非满足收敛条件。

回填后，如果实际 Top-1 token 与预期目标不同，应如实保留结果并分析原因，而不是为了符合叙述而修改数据。

**这就是语言模型最核心的输入输出关系**：给定前面的 token，预测下一个 token 的概率分布。

**模型结构：简化的单 Block、单头 Transformer 语言模型**

```text
token embedding + 位置编码 (10×3)
      ↓
单头 Self-Attention + Causal Mask + Pad Mask
      ↓
Add & LayerNorm
      ↓
FFN
      ↓
Add & LayerNorm
      ↓
输出投影 (W_O)
      ↓
Logits (10×12)
      ↓
Softmax
      ↓
概率分布 (10×12)
```

本书的 Transformer Block 在 Attention 和 FFN 后都使用残差连接（residual connection）和 LayerNorm，以帮助信息传播并稳定训练。Self-Attention 与 Mask 见第 5 章，残差连接、LayerNorm、FFN 和词表输出投影见第 6 章，softmax 与交叉熵损失见第 7 章。

## 0.7 为什么预测下一个 token 能够产生复杂能力？

训练目标看起来非常简单：

> 预测下一个 token。

例如：

```text
法国的首都是
```

正确答案：

```text
巴黎
```

为了在大量、多样的文本上持续降低预测误差，模型需要捕捉许多层次的统计规律，例如：

* 词义
* 语法
* 世界知识
* 文本中反复出现的推理模式
* 事件之间的相关性，以及语料所表达的部分因果关系

因为这些信息都会影响下一个 token 出现的概率。

从信息论角度看，概率预测与压缩紧密相连。若模型给真实出现的 token 分配概率 $p$，理想编码长度与 $-\log_2 p$ 成正比：概率估计越准确，平均编码长度通常越短。因此，降低交叉熵与发现文本中可压缩的统计结构，本质上是相互关联的目标。

Shannon 的信息论为概率与编码长度之间的关系奠定了基础。DeepMind 研究者在 2023 年的论文 *Language Modeling Is Compression* 中，又通过实验讨论了语言建模与通用数据压缩之间的联系。这里的“压缩”是一种理解视角，并不意味着语言模型与通用压缩器或人类智能完全等价。

直观地说，为了猜准下一个 token，模型会把“哪些 token 经常共同出现”“哪些语法结构更常见”以及语料中反复出现的事实模式编码进参数。至于这种内部表示是否构成与人类相同意义上的“理解”，是另一个需要单独讨论的问题；本书关注的是这些能力如何从可计算的统计学习过程中形成。

所以：

> 模型的训练目标很简单，但为了在广泛语料上完成这个目标，它需要在参数中编码大量统计规律。

这是理解大语言模型为何能从简单训练目标中表现出复杂能力的一种重要视角。

进一步说：

> 大语言模型学习的并不是某个孤立的“下一个 token”，而是影响后续 token 概率分布的各种规律。
